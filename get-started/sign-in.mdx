## Interactive (`compute setup`)

```bash
compute setup
```

The CLI starts a device flow, opens (or prints) a URL on [compute.cx](https://compute.cx), and waits for you to approve the device.

On success it writes `~/.compute/config.toml` with mode `0600`. The file holds a session token. Do not commit it. Do not paste it into chat.

`compute doctor --json` shows a sanitized identity after setup.

If you already have a dashboard session in the same browser, approve the CLI device and continue.

## CI (`COMPUTE_API_KEY`)

1. Sign in on [compute.cx](https://compute.cx/sign-in).
2. Open [API keys](https://compute.cx/keys).
3. Create a key. The secret is shown **once**.
4. Export it in the environment that runs `compute`:

```bash
export COMPUTE_API_KEY=ck_live_…
```

The environment variable wins over the config file. Revoke a leaked key from the same page.

## Sign-out / rotate

Delete `~/.compute/config.toml` or revoke the session/key from the dashboard. After revoke, new API calls should fail. If a request still works after ~10 seconds, treat that as a bug and include the request id from the error footer.
