---
title: Python SDK
description: App, Image, @app.function, and .remote(). Same HTTPS path as the CLI.
---

Install the CLI wheel first (`curl | sh`). That environment already has the `compute` package.

```python
import compute

app = compute.App("simple-mlp")
image = compute.Image.cuda_pytorch()


@app.function(gpu="H100-SXM", image=image, timeout=600)
def train(steps: int = 40) -> dict:
    import torch

    device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
    x = torch.randn(32, 8, device=device)
    return {"ok": True, "device": str(device), "mean": float(x.mean())}


if __name__ == "__main__":
    with app.run():
        print(train.remote(steps=40))
```

`.remote()` packs the function, uploads, creates a run on `/v1`, and waits for the result. It is not a local thread.

`gpu="H100"` or `gpu="H100-80GB"` normalize to **H100-SXM**.

You can also launch the same file from the CLI:

```bash
compute run train.py::train --gpu H100-SXM --wait
```

## Not in this manual

`.spawn()`, custom images beyond `Image.cuda_pytorch()`, volumes, and retries are not the public v0.1 path. If you see them in `--help` or the package, treat them as unsupported here until this page says otherwise.
