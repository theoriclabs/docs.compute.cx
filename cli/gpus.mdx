| `A100-80GB` | `A100-80` | Vast.ai interruptible | 80 GB datacenter |
| `H100-SXM` | — | Vast.ai interruptible | Same name as RunPod; qualify it |

`H100-SXM` exists on both RunPod and Vast.ai. A bare `--gpu H100-SXM` is ambiguous — use `--provider runpod` or `--provider vastai`, or write `vastai/H100-SXM`.

Vast.ai SKUs are **interruptible**. The host can reclaim the machine. Compute then ends the run and confirms teardown so you are not left paying for a paused box.

## Decorator vs CLI

```python
@app.function(gpu="H100-80GB", image=compute.Image.cuda_pytorch(), timeout=600)
```

```bash
compute run simple_mlp.py::train --gpu H100-SXM
compute run simple_mlp.py::train --provider vastai --gpu RTX-4090
```

The CLI `--gpu` / `--provider` flags win when both decorator and CLI are set. `simple_mlp.py` is in [First run](/get-started/first-run).

To choose from compatible GPUs using workload analysis:

```bash
compute run simple_mlp.py::train --gpu auto
compute run simple_mlp.py::train --gpu fastest
compute run simple_mlp.py::train --gpu cheapest
```

`auto` balances predicted execution time and provider cost. `fastest` and `cheapest` optimize one of those estimates directly. See [Run](/cli/run#automatic-routing) for the quote and confirmation flow.

## Images

- NVIDIA (RunPod and Vast.ai): `compute.Image.cuda_pytorch()`
- AMD: `compute.Image.rocm_pytorch()`

Use the image that matches the SKU. Mixing CUDA images onto MI300X (or the reverse) is a failed run, not a silent fallback.
