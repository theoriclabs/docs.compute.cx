---
title: Limits
description: Ten-minute default timeout, one fresh machine, no SSH.
---

Early access is capped. Admission, concurrent runs, and spend limits can reject a create even when you have credit. `compute doctor` and the API error footer carry a **request id**.

## Runtime

| Limit | Value |
|---|---|
| Default timeout | 10 minutes (`--timeout 600`) |
| Maximum timeout | 24 hours |
| GPUs per run | **1** — no multi-GPU shapes |
| Machine | **Fresh** for that run. No idle pool, no leftover disk |
| SSH | **None.** There is no customer shell on the box |

Payloads, results, and archived logs are deleted after **30 days**.

## What you should not expect

- A public REST “Try it” console
- PyPI (`pip install compute`) as the install path
- Persistent volumes or checkpoint resume
- Community/spot SKUs, A100, or 4090 in the public catalog
- The dashboard as a job launcher

If a create is rejected, the CLI prints an error code (`insufficient_funds`, admission, timeout, and so on). Do not retry in a tight loop.
